# Application Management

## Application Statuses

```text
DRAFT
SUBMITTED
UNDER_REVIEW
NEEDS_INFORMATION
APPROVED
REJECTED
```

## Application Flow

```text
DRAFT
  ↓
SUBMITTED
  ↓
UNDER_REVIEW
  ├──→ APPROVED
  │       ↓
  │    LICENSE
  │
  ├──→ REJECTED
  │
  └──→ NEEDS_INFORMATION
            ↓
       USER RESPONDS
            ↓
       UNDER_REVIEW
```

## Create Application

```http
POST /api/v1/applications
```

## List Applications

```http
GET /api/v1/applications
```

Support:

```text
page
limit
search
status
mediaType
dateFrom
dateTo
sortBy
sortOrder
```

## Get Application

```http
GET /api/v1/applications/:id
```

## Update Application

```http
PATCH /api/v1/applications/:id
```

## Submit Application

```http
POST /api/v1/applications/:id/submit
```

Before submission:

```text
Outlet information exists
Licensee information exists
Required documents exist
```

## Application Number

Generated by the backend.

Example:

```text
APP-2026-000001
```

Never trust the frontend to generate the application number.

## Status History

Every status transition must create:

```text
application_status_histories
```

Example:

```text
DRAFT
 ↓
SUBMITTED
 ↓
UNDER_REVIEW
 ↓
APPROVED
```

Each transition stores:

```text
from_status
to_status
changed_by
reason
created_at
```
